# 内容输入与工作目录

`dynamic-comic-video` 是可复用的生产 Skill。它的 GitHub 仓库不应成为用户故事、角色资产或成片的存档。

## 每次任务

1. 在仓库之外创建一个独立工作目录，例如 `work/<content-slug>/`。
2. 将本次用户 brief、角色参考、生成提示词、四份 JSON、master、图层、预览和 MP4 都写入该目录。
3. 使用仓库中的 `schemas/`、`scripts/` 和 `assets/remotion/` 作为能力模板；输入内容通过路径或参数传入，不修改通用示例。
4. 在该目录完成 validate、compile、视觉审阅和 Remotion 渲染。把 `qc_report.json` 与输出视频留在该内容目录，除非用户要求上传。
5. 只有用户明确要求发布某个内容项目时，才为它创建单独的内容仓库或单独分支，并在发布前再次确认可公开的素材与版权范围。

## 默认不写入仓库的内容

- 用户原始故事、脚本、采访、课程文本或品牌资料
- 用户角色设定图、身份参考图和私有素材
- 该内容的 prompts、storyboard、motion plan、master、图层、字幕和成片
- 含有用户隐私、未发布信息或第三方受限素材的日志和预览

通用测试夹具可以保留在 `examples/`，但必须与用户内容无关、可公开且能验证脚本行为。`projects/` 已被 `.gitignore` 排除，适合本地临时工作，不是内容发布机制。
