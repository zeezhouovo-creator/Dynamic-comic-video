# V0.4 制作闭环

V0.4 是 Dynamic Comic Video 的工作流版本。它把已经验证过的固定漫画机位、事件驱动表演和 Remotion 输出，收束成一条可以恢复、检查和局部返工的生产流程。

## 版本边界

- Skill 发布版本为 `0.4`；`motion_plan.version` 继续使用 `"0.3"`，三份基础合同继续使用 `"0.1"`。
- 这个分离是有意的：发布版本描述工作流能力，JSON 版本描述数据兼容性。没有不兼容字段变化时，不升级 schema 版本。
- V0.4 的目标是可检查的最小生产闭环，不承诺精确音素口型、骨骼绑定、完整逐帧动画、自动抠图或无人审核的全自动成片。

## 标准路径

```text
用户意图
  → Production Brief
  → Character Reference
  → Narrative Beats
  → Storyboard Director
  → Master Shot
  → Layer Planning
  → Motion Plan 0.3
  → 音频/字幕/动作统一时间轴
  → 漫画视听反馈
  → 质量闸门
  → Remotion 预览
  → 局部修正
  → MP4
```

入口先按 [动态漫画制作向导](production-wizard.md) 自动分流。用户只补充当前阶段缺失的信息；主题、地域、时代、事实边界和视觉语言不会因为默认示例被改写。

## V0.4 验收门

稳定版本验收至少用一个真实项目完成 3—5 个连续镜头，并留下以下可复查文件：

- `production_brief.json`、`characters.json`、`storyboard.json`、`motion_plan.json`
- 每镜 `master`、实际使用的图层和合成预览
- 配音、字幕事件、嘴型区间、动作事件和 CUT 位于同一时间轴
- `quality_report.json`，Critical 与 Major 数量为 0
- 一段可播放预览和最终 MP4 的输出记录

预览必须人工检查角色身份、场景空间、动作触发原因、静止阶段、字幕遮挡、音画同步和切镜因果。测试夹具只能验证脚本和渲染器，不能替代真实样片验收。

## 失败处理

质量闸门的自动修正范围由 [质量闸门说明](quality-gate.md) 定义，只限脚本支持的安全时间轴元数据。删改动作、音效或镜头属于制作决策，不能假定 `--autofix` 会完成。角色漂移、背景空间错误、master 构图失败和图层缺失必须回到对应阶段处理，不得用整体缩放、推拉或固定立绘循环掩盖。

用户反馈按模块最小化处理：人物僵硬回到动作事件，字幕太快回到音频时间轴，像 PPT 回到分镜变化与反应镜头，角色变脸回到 Character Reference 和该镜 master。已通过的剧情、角色和画风保持不动。

## 旧项目兼容

V0.3 项目可以直接读取。升级后先运行质量闸门和预览，不需要批量重生成 master 或修改 JSON 版本。只有当未来引入不兼容字段、时间单位或渲染语义时，才创建新的 schema 版本并提供迁移脚本。
